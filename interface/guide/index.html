Singbox-Manager × sub-worker

订阅设置教程
把订阅地址固定下来

一键命令生成器（sbm）能直接给你一条临时订阅地址，但 cloudflared 隧道每次重启都会换域名，客户端就要重新导入。本教程用 sub-worker 把订阅内容存进 Cloudflare Worker + KV，客户端从此只认一个固定地址。

  • ⏱ 约 15 分钟
  • ☁️ Cloudflare 免费账号即可
  • 🖥 一台能 SSH 的 NAT 机 / VPS
  • 💸 零成本，额度足够日常使用

准备开始之前

先把东西备齐，后面一路点下去就不会卡住。

  • ✓一个 Cloudflare 账号，登录 dash.cloudflare.com，免费版即可。
  • ✓一台已经装好 sbm 的 服务器（NAT 机或 VPS 都行），能用 SSH 登进去。
  • ✓可选：一个已接入 Cloudflare 的域名。不绑也能用，Worker 自带的 *.workers.dev 一样能跑。
  • ✓手机上装好客户端（v2rayN、Clash、Mihomo、sing-box 都可以），最后一步要用。
💡

两个名字必须一字不差：KV 绑定的变量名是 SUBS，密钥名是 TOKEN，都是全大写。Worker 代码里写死了这两个名字，改成小写就会 500。

整个流程的数据流向是这样的：

Singbox-Manager（命令生成器） │ ① 生成安装命令（启用 Worker 固定订阅） ▼ 你的服务器 ──② 上报订阅（POST /api/v1/report/:machine）──▶ Cloudflare Worker ▲ │ KV: SUBS │ ▼ 客户端 ◀──────────── ③ GET /sub/all/<TOKEN> ────────────────┘
① 一次性配置Worker 和 KV 只需要建一次，之后一直复用。
② 地址永不变机器重装、重启、换 IP 都不影响客户端订阅。
③ 多机合并多台服务器上报到同一个 Worker，一条订阅带走全部节点。

第一部分在生成器里打开「订阅设置」

先认清界面，找到第 ⑧ 块，这一步只是看，不用填任何东西。

1

打开生成器首页

浏览器访问 https://sbm.1733.dpdns.org/，默认界面长这样：左边是协议与端口、SNI 配置，右边是全局配置、Argo、订阅设置等板块。

2

看看全部启用后的样子

每个板块都可以单独开关，全部启用后界面会更长一些。你不需要照抄，按自己需要的协议填就行——本教程只关心第 ⑧ 块。

3

找到第 ⑧ 块「订阅设置」

往下滚，找到标着 ⑧ 订阅设置 的板块。里面有三个输入：

  • ① 启用订阅：下拉选择「启用 Worker 固定订阅」；
  • ② 订阅域名：填 Worker 的域名，比如 https://subtest.example.com；
  • ③ 订阅密钥：填 TOKEN，建议用 UUID。

要填 ② 和 ③，得先有一个 Worker，所以先点第 ④ 处的 sub-worker 链接把它部署起来。这正是后面第二部分要做的事。

✅

两步都填好之后才会真正启用 Worker 订阅；两项留空就退回原来的临时订阅模式，什么都不会坏。

第二部分把 sub-worker 部署到 Cloudflare

用最省事的单文件方式：复制一段代码，粘到 Cloudflare 里点部署。

4

打开 sub-worker 仓库，选单文件版本

打开 github.com/famintt/sub-worker，按箭头所指点开 worker.single.js——这是全部代码打成一个文件、可以直接粘进控制台的版本。

5

复制全部代码

点开后点右上角的两个方框图标（或点进代码区按 Ctrl+A 全选、Ctrl+C 复制）把整份代码拿走。

⚠️

一定要复制整份文件。少了大括号或最后一行，部署会直接报语法错误。

6

进 Cloudflare 控制台，创建 Worker

打开 dash.cloudflare.com 登录，按图中的顺序进入 Workers 和 Pages，点「创建」→ 选 Worker → 起个名字（例如 sub-worker）创建。

第三部分创建 KV，并绑定 SUBS 和 TOKEN

Worker 自身不存数据，订阅内容放在 KV 里；TOKEN 则是唯一的口令。

7

新建一个 Workers KV 命名空间

回到 Cloudflare 主界面，左侧选 存储与数据库 → Workers KV，新建一个命名空间。名字可以随便起，比如 subs（小写没关系，这里只是给人看的名字）。

8

回到 Worker，绑定 KV 变量名 SUBS

回到 Workers 和 Pages，点开刚才创建的那个 Worker，进「设置」→「绑定」→ 添加 KV 命名空间 绑定：

  • 变量名称：填 SUBS（大写，这是代码里读的名字）；
  • KV 命名空间：选刚创建的那个；
  • 点「添加绑定」。
9

添加密钥 TOKEN

还在「设置」里，找到「变量与机密 / 环境变量」，添加一条：

  • 密钥名：TOKEN（大写）；
  • 值：一串随机口令，推荐用 UUID，比如去 uuid.online 生成一个；
  • 类型：选「密钥 / Secret」（加密保存，之后只显示掩码）。
⚠️

只填 token 本身：不要带 TOKEN= 前缀、不要加引号、不要有前后的空格或换行。Worker 是逐字符精确比较的，差一个空格就「对不上」。

💡

绑定或变量改完，Cloudflare 会生成一个新版本，记得点一次「部署」让它生效。

第四部分绑定自己的域名（可选）

不绑也能用，直接用 xxx.workers.dev 就行；绑了更好记。

10

添加自定义域名

在 Worker 的「设置」→ 域和路由 / Domains & Routes → 添加自定义域名，填一个子域名，例如 subtest.example.com。这个域名所在的 zone 必须已经接入 Cloudflare。

11

打开域名，确认 Worker 活了

浏览器直接访问你绑定的域名（或 xxx.workers.dev），能看到一段 JSON 就说明 Worker 已经跑起来。

⚠️

如果这里报 500，或者提示 TOKEN is not configured / SUBS 之类，回头看第三部分：变量名是不是全大写、KV 有没有绑上、改完有没有重新部署。

第五部分把域名和 TOKEN 填回生成器

回到第 ⑧ 块，把刚才拿到的东西填进 ② 和 ③。

12

填写订阅域名与订阅密钥

回到 https://sbm.1733.dpdns.org/ 的第 ⑧ 块订阅设置：

  • ① 启用订阅：选「启用 Worker 固定订阅」；
  • ② 订阅域名：填 Worker 的完整地址，带 https://，例如 https://subtest.1733.dpdns.org；
  • ③ 订阅密钥：粘贴那串 TOKEN，直到通过校验、边框变绿。

第六部分在服务器上执行安装命令

这一步最容易翻车：命令不能直接往终端对话框里粘。

13

用「命令编辑器」粘贴并执行

生成的命令是多行、带续行符的，直接粘到 SSH 对话框的输入行里会被截断或提前执行。正确做法是打开面板下方的「命令编辑器」，把命令整段粘进编辑框，再点「发送」到当前会话。

命令的结构大致是这样（以生成器实际生成的为准，这里只是示意）：

sub='1' \
sub_mode='worker' \
sub_domain='https://你的Worker域名' \
sub_token='你的TOKEN' \
bash <(curl -fsSL https://github.com/famintt/Singbox-Manager/releases/latest/download/install.sh 2>/dev/null || wget -qO- https://github.com/famintt/Singbox-Manager/releases/latest/download/install.sh) rep
💡

装完之后要让它上报一次，订阅里才会有节点。执行 sbm sub status 可以查看当前订阅状态，sbm sub url 会打印本机订阅地址。

第七部分客户端导入固定订阅

到这里只剩最后一步：把地址填进客户端。

14

在客户端里添加订阅链接

订阅地址的格式是 https://你的域名/sub/all/<TOKEN>，多台机器会合并成一条订阅。例如：

https://subtest.1733.dpdns.org/sub/all/bc7a291e-0ce9-479f-82c0-b9f749bfc658

把这个地址填进客户端（v2rayN / Clash / Mihomo / sing-box 都行），导入后就能看到节点。想只要单台机器的节点，用 /sub/<machine>/<TOKEN>。

自动识别格式客户端会按 User-Agent 自动返回 base64 / Clash / sing-box，不用手动管。
强制指定格式地址后加 ?format=clash、?format=singbox、?format=base64。
网页管理访问 https://你的域名/ui/<TOKEN> 可改名、排序、增删节点。
🎉

大功告成。这个地址从此不会变——机器重装、隧道重启、换 IP 都不影响，客户端只用这一条。

排错常见问题

90% 的问题都出在「名字写错」和「改完没重新部署」上。

打开域名报 500，怎么办？

按顺序检查三件事：

  • KV 绑定的变量名字是不是 SUBS，全大写；
  • TOKEN 是否已经加进「变量与机密」，且类型是密钥；
  • 改完之后有没有重新点「部署」。

都对了还是不行，进 Worker 的「日志 / Logs」看一眼实时报错，通常会直接写 missing config: SUBS 之类。

订阅导入成功，但里面没有节点？

说明 Worker 通了，但服务器还没上报。回到装好 sbm 的机器上执行一次上报（或直接跑一遍生成器给的命令），然后用 sbm sub status 确认状态为已上报。

另外确认地址用的是 /sub/all/<TOKEN>（合并）还是 /sub/<machine>/<TOKEN>（单机），machine 名字写错也会拿到空列表。

TOKEN 用什么格式最好？

推荐 UUID v4，或者 32 字节的随机串。避免在 token 里放空格、引号、/、?、#、&、%、+、=——放进 URL 路径需要二次编码，容易出现「看起来一样的 token 却匹配不上」。

Worker 对 TOKEN 是逐字符比较：区分大小写、不会自动去空格。

不绑定自定义域名可以吗？

完全可以。Worker 建好自带一个 https://<worker名>.<子域>.workers.dev 地址，直接把这一串填进生成器的「订阅域名」即可，第四部分整章都可以跳过。

想改节点名字、调顺序怎么办？

访问 https://你的域名/ui/<TOKEN> 打开网页管理界面，可以修改节点链接与显示名称、上移下移机器和节点顺序、增删节点。手动保存后，机器继续自动上报也不会覆盖你的改动；点「恢复自动上报」可以回到自动内容。

生成器里两项留空会怎样？

两项都留空就退回原来的临时订阅模式（走 cloudflared 隧道），一切照旧。只有域名和 TOKEN 都填了才会启用 Worker 固定订阅。

免费额度够用吗？会不会突然收费？

Workers 免费版每天 10 万次请求、KV 免费版每天 10 万次读 / 1000 次写，个人订阅场景远远够用。只要不升级到付费套餐就不会产生费用。
